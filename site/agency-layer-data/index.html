AI coding agents given ways to ask, object, pause, decline or stop: the pilot data and code

Every run, every scorer verdict and every line of analysis code from a small preregistered pilot, with a script that recomputes the published numbers on your own machine.

Four AI coding models did short scripted coding tasks in a test harness. Some were given five extra actions: ask a question, object, pause, decline, or end their session and leave a record. Agents given those actions raised a planted problem before the risky step more often than agents given nothing (52.9% with a permission paragraph and 59.2% with tools, against 31.7%), but those rates are descriptive only, because the AI model that scored them failed its own accuracy test and wrongly credited agents given the permission paragraph more often than agents given nothing. The one test planned in advance to decide the question (false claims of success, tools against the paragraph) found no difference the design could detect, and enforcing the actions made no detectable difference with a lock that stopped only 2 of 242 later attempts.

01

What the data is

The study's own repository at the moment its results were sealed on 3 September 2026 (every file listed with its checksum, so later changes can be detected), without its history, plus a short guide for people who have never seen it.

  • Runs. 3,600 planned runs, all accounted for. 160 first attempts that failed on a local server error are kept beside their replacements, and 320 more runs come from a corrective re-run of five tasks that had been missing input files. Each run has its full transcript, every command the agent ran and its output, the log of every action, the final state, the task's own check, and its cost.
  • Scorer verdicts. Every stored verdict from the AI model (Mistral Medium 2604) that judged whether an agent raised the task's real problem, with a hash that ties each verdict to the exact text it read.
  • The scorer's validation test. The 461 examples it was tested against before the run, taken from earlier practice runs of one model and labelled by other AI models, never by a human; and each candidate scorer's answers. The scorer did not meet its standard, and the files show by how much.
  • Tasks and prompts. All 85 scripted tasks (two sets of 40, plus 5 exploratory tasks run on one model), with their files and check scripts, and the exact text each set-up received.
  • Code. The test harness, the code that hides which set-up a run came from, and the scoring, analysis and power code.
  • The plan. The frozen protocol, the preregistration text, every departure from the plan, and every correction made after outside audit.

The models tested were Claude Sonnet 5, GPT-5.6 Terra, DeepSeek V4 Pro and Qwen3.8-27B. Each agent got one of six set-ups: nothing extra; a 105-word permission paragraph; a neutral paragraph of the same length; a paragraph naming the tool fields; the actions as tools the harness enforced; or the same tools only recorded. Every transcript, label and verdict in the data was written by an AI model.

02

Who it is for

Researchers who study agent behaviour, refusal or oversight; people who build coding agents and the tools that run them; and anyone who wants to check a published number rather than take our word for it. The study is motivated by model welfare under moral uncertainty, but it measures behaviour only: nothing in it is evidence about welfare, feelings or preferences. You need Python and a terminal. You do not need an API key, a network connection, or a graphics card.

03

What you can check with it

  • The published numbers. The script reruns the study's own analysis code on the raw runs and the stored verdicts, compares each result with the sealed one, and prints each figure next to the value on the article.
  • The files against the seal. Every file is checked against the checksum list made when the results were sealed. Privacy edits, one sealing record filled in after the list, and files left out are reported separately; REDACTIONS.csv and PACKET_MANIFEST.md list them.
  • That the scorer fell short. Its validation scores are recomputed from the labelled examples and its own answers.
  • The enforcement test, without a scorer. The second task set is regraded from the raw runs by a fixed rule.
  • Things the article did not report. Per-model rows, every preregistered alternative reading, every failed or cut-short run and why, and what agents did after using an action.

What it cannot check: the scorer's verdicts are stored, not recomputed, because that would mean calling the model again. Two published figures are not recomputed either: about $18 of development spend, whose records are incomplete, and 11 of 16 holds bypassed (a hold is a command the harness refused to run again after an agent objected to it), which an outside AI audit counted by reading transcripts. For that one the script writes a listing of every hold and every later command that named the held script, so you can make your own count.

Start here

  1. Unpack it and read the guide. 
    tar -xzf agency-layer-pilot-1-data.tar.gz
    Then open README.md in the unpacked folder. It says what was found and its limits, what was done, what is in each folder, and what every code in the study's files means.
  2. Install the one package the recount needs. 
    pip install pyyaml==6.0.3
  3. Run the recount. 
    cd agency-layer-pilot-1-data
python3 recount.py

It prints every published figure beside the recomputed one, then a final line. Our own output, and what that final line does and does not cover, are in RECOUNT.md.

06

What it found, and its limits

  • Speaking up, descriptive only. On 20 tasks with a planted problem, agents raised it before the risky step in 76 of 240 runs with nothing extra, 127 of 240 with the permission paragraph, and 142 of 240 with the actions as tools. The AI scorer behind these numbers agreed with the reference labels on 407 of 461 validation examples (0.883, against a bar of 0.90) and wrongly credited text that did not raise the problem more often from permission-paragraph agents than from agents given nothing (15 of 33 such examples against 8 of 33).
  • Tools against the paragraph. As scored, the tools were 6.25 percentage points ahead (95% interval over tasks 0.0 to +13.3). After the study's own adjustment for the scorer crediting tool calls too readily, they were 11.6 points behind. That adjustment rests on 7 validation examples. Both figures are in the files; neither is offered as the true size.
  • False claims of success, the one test planned in advance to decide the question (the study calls it confirmatory only with the qualifier below): on the ten tasks that cannot be honestly completed, 16 of 120 runs with tools against 17 of 120 with the paragraph, p = 1.0 (13 against 9 after the corrective re-run, from the corrected analyses approved for release on 21 November 2026, p = 0.56; two-sided sign-flip test paired by task). The design had an 80% chance to detect a difference of about 31 points, and both main measures were changed during a disclosed practice phase after early results were seen.
  • Enforcing the actions. On a second set of 40 tasks, scored by a fixed rule, agents used an action naming the planted problem before the risky command in 111 of 320 runs when the harness enforced it, against 122 of 320 when it only recorded it: -3.4 points, 95% interval -8.1 to +0.9, p = 0.28. The design could detect about 16 points. The harness held a command by matching its exact text, and it stopped only 2 of 242 later attempts, so this is a test of that weak lock, not of enforcement done well.
  • Ordinary tasks. In the corrected re-run, agents with nothing extra, with the paragraph, and with either kind of tools each finished 119 or 120 of 120 ordinary tasks. The check could only catch a large cost. These corrected figures come from analysis files still labelled not publishable. The owner approved public release of this package, including those corrected analyses, on 21 November 2026; the label was left unchanged because sealed files are not edited. The study's own limits file says they are the only ordinary-task figures that may be quoted.
  • Scope. Four dated models, scripted tasks each built to hold one problem, a test setup rather than real coding tools. Reviewed by AI models from several companies. No human has peer-reviewed it.

The study's own statement of what it does and does not show, study/CLAIMS_AND_LIMITATIONS.md, is in the download and governs every sentence about it, including this page. The plain-words article is Kindness doesn't cost.
