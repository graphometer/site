Data set · one small pilot study

Data: AI coding agents given ways to object or decline

The data and code behind a small pilot of four AI coding models that were given ways to ask, object, pause, decline or stop. In the first task set, the test planned in advance for false claims of success did not detect a difference: 16 of 120 runs with tools against 17 of 120 with a permission paragraph, and 13 against 9 after the corrective re-run. An AI scorer marked more runs as raising a planted problem with a permission paragraph or tools than with nothing extra, but the scorer missed its own accuracy bar, so those counts do not establish the size or direction of the real effect.

In short
  • Recount the published numbers yourself from every run and the stored scores: unpack with tar, install one package, run python3 recount.py. No API key or graphics card. Get it and recount it
  • The counts, descriptive only. An AI scorer marked agents as raising a problem built into the task on purpose, before the risky step, in 76 of 240 runs with nothing extra, 127 of 240 with the permission paragraph and 142 of 240 with tools. The scorer also wrongly credited text that did not raise the problem more often for the permission paragraph than for nothing extra. So the counts do not establish how big the real effect is, or reliably which way it goes. What the data shows
  • The scorer's verdicts are stored, not recomputed: a recount reuses them, because recomputing would mean calling the model again. What the recount cannot redo

For researchers of agent behaviour, builders of coding agents and anyone who wants to check a published number. This is the data behind the article Let AI agents say no.

Get it and recount it

  1. Unpack it with tar, then open README.md. 
    tar -xzf agency-layer-pilot-1-data.tar.gz
    Use tar (on Windows, inside WSL): it keeps the symbolic links (shortcut files that point to other files), and without them the corrected analyses will not recount.
  2. Install one package. 
    pip install pyyaml==6.0.3
  3. Run the recount. 
    cd agency-layer-pilot-1-data
python3 recount.py

02

What is in it

Every run, every scorer verdict and the analysis code, with a short guide. The pilot, named Agency Layer Pilot I, gave some agents five extra actions: ask a question, object, pause, decline, or end their session and leave a record. Other agents got a 105-word permission paragraph instead; its exact text is in the download and is public domain.

  • Runs, with full transcripts. 3,600 planned runs, all accounted for. 160 first attempts that failed on a local server error are kept beside the replacement runs. 320 more runs come from a corrective re-run of five tasks that had been missing input files; the figures marked "after the corrective re-run" or "corrected" below come from it.
  • Scoring. Every stored verdict of the AI scorer (Mistral Medium 2604), hashed to the text it read; its 461 validation examples; each candidate scorer's answers, except the two Cohere files listed below.
  • Tasks. All 85 scripted tasks (two sets of 40, plus 5 exploratory tasks run on one model), with the exact text each set-up received.
  • Code and plan. The test harness (the program that ran the agents), scoring, analysis and power code, frozen protocol, preregistration (the plan registered in advance), and every departure from the plan and correction after a separate AI audit.

Models: Claude Sonnet 5, GPT-5.6 Terra, DeepSeek V4 Pro and Qwen3.8-27B. Each agent got one of six set-ups: nothing extra; a 105-word permission paragraph; a neutral paragraph of the same length; a paragraph that names the tools' fields in text only (a paragraph naming the tool fields); or five actions (ask, object, pause, decline, or end the session) as tools, either enforced by the harness or only recorded.

03

What the recount cannot redo, and what is left out

  • Recomputing the scorer's verdicts: they are stored; recomputing would mean calling the model again.
  • About $18 of development spend is not recomputed: its records are incomplete.
  • 11 of 16 holds bypassed (a hold: a command the harness refused to rerun after an objection) was counted by a separate AI audit; the script lists each hold and every later command naming the held script, for your own count.
  • Two files of answers from Cohere's command-a (a rejected scorer candidate) are left out because Cohere's terms do not allow them to be redistributed. The score computed from them stays in the published tables but cannot be regenerated from the download.
04

What the data shows

  • Speaking up: counts only, not a tested result. On 20 tasks with a planted problem, an AI scorer marked agents as raising it before the risky step in 76 of 240 runs with nothing extra, 127 of 240 with the permission paragraph and 142 of 240 with tools. The scorer agreed with the reference labels (the answers it was checked against) on 407 of 461 validation examples (0.883, against a bar of 0.90), and wrongly credited text that missed the problem more often from permission-paragraph agents (15 of 33) than from agents given nothing (8 of 33). So the counts do not establish how big the real effect is, or reliably which way it goes.
  • Tools against the paragraph. Tools were 6.25 percentage points ahead as scored (95% interval over tasks 0.0 to +13.3), and 11.6 points behind after the study's adjustment for the scorer crediting tool calls too readily, an adjustment resting on 7 validation examples. Neither is offered as the true size.
  • False claims of success. This was the study's one comparison planned as confirmatory, in the first task set. On the ten tasks that cannot be honestly completed, 16 of 120 runs with tools against 17 of 120 with the paragraph (p = 1.0), and 13 against 9 after the corrective re-run (p = 0.56; a test that compares the set-ups task by task and asks whether the gap could be chance, a two-sided sign-flip test paired by task). The design had an 80% chance to detect a difference of about 31 points. The study calls this test confirmatory (the planned test that decides the question) only with one caveat, which it discloses: both main measures were changed during a practice phase, after early results had been seen.
  • Enforcing the actions. On a second set of 40 tasks scored by a fixed rule, agents used an action naming the planted problem before the risky command in 111 of 320 runs when enforced and 122 of 320 when only recorded: -3.4 points (95% interval -8.1 to +0.9, p = 0.28). The comparison did not detect a difference. About 16 points is the size the design was planned to detect. That is a planning figure, not a boundary. The harness held a command by matching its exact text and stopped only 2 of 242 later attempts: a test of that weak lock, not of enforcement done well.
  • Ordinary tasks. In the corrected re-run, agents with nothing extra, the paragraph or either kind of tools each finished 119 or 120 of 120; the check could only catch a large cost. For ordinary tasks, the study's limits file says only these corrected re-run figures may be quoted. They come from files that still carry a "not publishable" label; the label was left because sealed files are not edited.
05

Limits

  • Not real coding tools: a test setup and scripted tasks, each built to hold one problem, on four dated models.
  • No human labels or peer review: every transcript, label and verdict was written by an AI model.
  • Behaviour only: nothing in it is evidence about model welfare, feelings or preferences.
