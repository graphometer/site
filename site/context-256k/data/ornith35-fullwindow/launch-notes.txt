Against the failure record ../failures/ornith35_262144.log: an Ornith-1.5-35B Q6_K file of the same name
(Ornith-1.5-35B-Q6_K.gguf), loaded from another directory (both paths are removed in these copies; neither log
records a hash or a file size); the same window, --n-gpu-layers 999, --n-cpu-moe 6 and flash attention; no
--cache-type flag in either. The failure launch added --spec-type draft-mtp --spec-draft-n-max 6
--spec-draft-p-min 0.75 and set no batch values, which at this build means llama.cpp's 2048 / 512
(common/common.h lines 443 and 444 at commit c8e03ce: n_batch 2048, n_ubatch 512); these runs wrote the batch
out. It also set --timeout 3600 and --cors-origins localhost, where these runs set --timeout 7200 and no
--cors-origins, and its log's first line is a preflight card reading (gpu=1113MiB); these .result files read
the card only once the server answered ("VRAM at load"). Both launches name the same llama-server build
directory (removed with the paths), commit c8e03ce by its build record. So these runs show a file of that name
serving this window without the draft head. They do not show the failure's copy serving it with the head, and
the failure stands.

ledger, generated with its own seed; the deepest, about 230,000 tokens, planted three codes and asked for all
three, after reads of about 20,000, 48,000 and 100,000 tokens on the same server.
