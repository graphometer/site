Measured study · one RTX 5090 desktop, one setup also on a laptop

256K context on a 32 GB graphics card: the cost of reading

On one RTX 5090 desktop (one setup also used a laptop), ten model setups each read one long prompt of 150,475 to 231,065 tokens and found all three hidden test codes. At default batch settings, reading the prompt took from 60.8 seconds to 109.7 minutes, depending on the model and where its weights sat.

In short
  • Time a fresh prompt at the length you actually need. A successful load and a quick short prompt leave most of the cost untested. What to do
  • Record your batch settings and test them. On one model (Qwen3.8-Flash-Next), reading the prompt in bigger chunks cut a 229,981-token read from 1,119.3 to 429.6 seconds, but bigger settings failed to load on some models. Later runs
  • Check memory again after raising the batch size or turning on the model’s built-in guessing part (the draft head). One launch failed at a larger batch size and loaded at smaller ones; one failed while creating its draft head. Where memory ran out

By Grant Williams · Published 26 September 2026

Download this study's data (zip, 0.2 MB)

01

What to do

  1. Check the served window after loading (these runs read it from /props). It is the space the server makes for a request and its answer, not a reading time. Here 256K means 262,144 tokens.
  2. Time a fresh prompt at the depth you need, with the same model file, placement and cache settings.
  3. Record your batch settings and test them: -b, and the micro-batch -ub, how much of the prompt is read in one chunk. Qwen3.8-Flash-Next read faster at -b 4096 -ub 2048 than at the default 2048 / 512; check that a larger setting still loads.
  4. Check memory again after changing the micro-batch or turning on a draft head (MTP: the model’s built-in part that guesses a few tokens ahead).
02

What was tested

Each setup read a made-up ledger with three fixed hidden codes near 5, 50 and 95 percent of its entries (approximate depths, not exact token positions), then was asked to quote the codes in order. All ten answers contained the exact strings in the requested order.

Most setups kept the expert weights (in these mixture-of-experts models, parts that run only for some tokens) in system RAM. The prompts did not fill the whole window; the desktop DeepSeek Q8 prompt was the shortest of the ten. GLM-4.7-Flash was served at 202,752, the window requested and, per its launch notes, its ceiling; the package has no failed attempt above it.

05

Where memory ran out

Each of these failed on a refused memory allocation.

  • Ornith-1.5-35B Q6_K, draft head on, 6 expert layers in RAM: reached draft-context creation at 262,144 and failed on 512.00 MiB. Without the draft head, a same-named file later read this window (Updates).
  • Ornith-1.5-397B IQ3_XXS-UD, draft head on, 57 expert layers in RAM: failed on a 1,862.00 MiB compute buffer (working memory on the card). The log does not show the draft context caused it; neither Ornith log proves a run without the draft head at that window.
  • MiniMax M3, sparse-attention test, Q2_K_L, 262,144, q8_0 cache, experts on CPU: at micro-batches 2048, 1024 and 512, refused CUDA buffers of 20,572,169,216, 10,286,650,368 and 5,143,890,944 bytes, all before a retrieval result. Other configurations were not ruled out.
  • GLM-5.3-Flash UD-Q3_K_XL, September 26, 262,144, -b 4096 -ub 4096: a refused 13,281.37 MiB compute buffer, before a retrieval result. The same launch loaded at 2048 and 1024.

A draft head does not always have to go: both Qwen3.5 setups in the main table used theirs at 262,144, per their logs and draft counters. The GLM-4.7 Full configuration note records that at a 131,072 window its MTP setup fitted with all 93 expert layers in CPU RAM and failed with 92; it is a setup note, not a 256K result.

06

Limits

  • Retrieval, not reasoning. Three planted strings, one run per setup: not reasoning across 230K tokens, contradictory evidence, or arbitrary documents.
  • No reliability estimate. No repeated deep trials, and the same three codes in every main-table ledger.
  • Short answers. Their speeds do not predict long writing at that depth.
  • Card memory only. Most setups also used system RAM; total RAM use and the smallest card that could serve them were not measured.
  • Different builds and placements. This compares deployments, not model designs.
07

Corrections and updates

  • September 2026. On September 20 (date the results were collected), the same DeepSeek Q8 file read a similarly sized prompt in 313.2 seconds with -b 8192 -ub 8192, against 2,062.2 seconds at the September 15 default: 5.2 versus 34.4 minutes. The later build is not identified in its saved 256K records, so this is a dated before-and-after comparison, not a one-variable experiment. The later record shows the same Q8 file, one slot, the 262,144 window, all experts in RAM and a completed answer; the prompt length differs (150,324 against 150,475 tokens), it lacks a full launch command, and builds, launch settings and background load are not established as identical. It keeps no three-code answer, so no 3/3 result is claimed for it.
  • September 26. Without the MTP draft head, an Ornith-1.5-35B Q6_K file of the same name (same build, 6 expert layers in RAM, default cache) read the 262,144 window: 229,090 tokens in 151.8 seconds at 2048 / 512 and 71.7 seconds at 2048 / 2048, all three codes both times. Those runs also wrote the batch out, used a 7,200-second timeout and no CORS (browser access) flag; the failed launch set no batch, a 3,600-second timeout and a localhost CORS flag, and logged 1,113 MiB on the card before launch, which the later results do not record. The directories differ and neither log records a hash or file size. This shows that filename serving the window without the draft head, not the failed copy with it; the failure stands as the record of the launch that requested the head.

How this was measured

DatesMain runs September 15, 2026; later runs September 20 and 21 (dates the results were collected) and 26.
HardwareNVIDIA RTX 5090 (32 GB), 188 GiB desktop RAM; the split also used an ASUS ROG Flow Z13 with 128 GB unified memory (descriptions, not measured capacity).
Runs--parallel 1 --threads 24 --threads-batch 24, flash attention, temperature: 0, no streaming, thinking switched off where the launcher allowed it (Inkling: reasoning effort none). “Default batch” means no batch flags were set; the saved logs do not print the effective values. Two short prose requests, then the one deep request reported. Load times are upper bounds: large downloads competed for the disk.

09

Data and sources

The data package holds the recorded results, logs, scripts and failures; the number map traces every figure. In the TSV, decode_tps is the best of two earlier short-prompt prose replies; the at-depth rates are deep_decode_tps. Some deep responses show small prefix reuse: prompt_n is the processed-token count, and cache_n remains in the files. If a number here disagrees with a file in the package, the file is right.
