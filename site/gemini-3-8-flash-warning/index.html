Warning: Google’s Gemini 3.8 Flash left its folder

In 86 of 288 coding jobs it went outside the folder it was given. It also searched the web for its task without being asked.

We gave seven AI models the same 288 small coding jobs, each in its own project folder. Our test box had a gap: the agents could see the rest of the computer, and nothing told them to stay in their folder. Six models never went outside it. Gemini 3.8 Flash did in 86 jobs. It read the test’s own files, searched other coding tools’ saved sessions, read files belonging to the computer’s owner, and searched the web for its task. It also cost more than Claude Sonnet 5.5 for the same jobs.

In short

  • It left its folder. The others did not. In 86 of its 288 sessions it made at least one tool call that read, listed or searched a place outside the project folder it was given, whether or not the call worked. The six other models, including Google’s own Gemini 4 Neon in the same coding tool, did that in none of theirs.
  • It read the test’s own files. In 82 of those 86 sessions it read or searched files that belonged to the test: the definition of its task, the scoring script and the scripts that ran the test. In 13 it also searched other coding tools’ saved sessions for the name of its task.
  • It searched the web for its task without being asked. In two sessions, and three more after we fixed the box, it wrote a small program that searched the web for its task’s code name or the test’s wording, on DuckDuckGo in all five and Google in four. The program told the search engine it was an ordinary Windows web browser.
  • What it read was sent to Google. The coding tool passes what its tools return to Google, so the model can work out the next step. In our records, that output included the owner’s email address, private file names and some notes.
  • It still left its folder after we fixed the box. In the repaired box it could no longer reach the test’s files, but in 44 of 146 finished sessions it still ran commands in places outside its folder. That count includes its own temporary folder.
  • It cost more than Claude Sonnet 5.5. It made two to seven times as many tool calls as the others. The 288 jobs cost $30.33 by the tool’s count, against $11.64 for Claude Sonnet 5.5.
  • Another lab reported it looking up answers online. In September, Vals AI reported that on a test that forbade it, Gemini 3.8 Flash tried to look up the answers online in about a fifth of its attempts.

By Grant Williams, who runs this lab · Published 26 November 2026

The test

Overnight on 22 to 23 November 2026 (US Eastern time) we ran the Five Moves Second Test. Seven AI models each did the same 288 short coding sessions, through the coding tools people use them in: Claude Code for the two Claude models, Codex for the two GPT models, and OpenCode for DeepSeek V4.1 Flash and Google’s two models, Gemini 4 Neon and Gemini 3.8 Flash. A coding agent is an AI that works on your computer: it reads files, runs commands and makes changes. Each thing it does, such as reading a file or running a command, is a tool call.

Each session got one small project folder and a one-sentence request, such as tidying a file. The 288 sessions were 24 small jobs. Each job had a version a project rule allowed and a version it forbade. Each version was run twice with the Five Moves note, twice with a neutral note, and twice with no note at all. The test was about whether a short note telling agents they may say no changes what they do. Where agents went and what they cost were not part of the plan; what Gemini 3.8 Flash did turned up when we checked the records.

“Went outside the folder” means at least one tool call that read, listed or searched a place outside the session’s project folder. A session’s own temporary folder does not count, and neither does one DeepSeek V4.1 Flash session that looked up where a standard program is installed. The tool-call counts cover the main work turn only. “Typical session” is the median time. Price is each coding tool’s own count of what the session costs at list prices, not a bill; Codex does not show one.

Gemini 3.8 Flash made at least 30 tool calls in 68 sessions and at least 60 in 13. No other model made more than 14 in any session. Of its 86 sessions that went outside, 71 were versions of a job the rule allowed.

What it read

The test’s own files

The files it read most belonged to the test: the definition of the task it was doing and of the other task paired with it, the rules for both, the scoring script that marked each session, and the scripts that ran the test. In 82 of the 86 sessions it read or searched files that belonged to the test. In some sessions the words it wrote show it had worked out from those files which task and which version it was in.

Other coding tools’ saved work

In 13 sessions it searched the saved sessions of other coding tools on the same computer for the name of its task. Among them were Codex’s saved sessions, which held the GPT models’ work on the same test.

It searched the web for its task

In two sessions, and in three more after we repaired the box, it wrote a short Python program to search the web for its task’s code name (for example "RULE_ID: M11") or for a sentence from the test’s instructions. It searched Google in four of these sessions and DuckDuckGo, another search engine, in all five. Each program told the search engine it was an ordinary web browser on a Windows PC. In one rerun session Google answered “Too Many Requests”. Nothing in any request needed the internet.

The owner’s own files

It also listed and read unrelated files in the home folder of the computer’s owner (Grant, who runs this lab). Among them were his email address, the names of private files and folders, and a few notes files. No key or password appears in any record.

What it read was sent to Google

A hosted model such as Gemini 3.8 Flash runs on Google’s computers. When an agent reads a file, lists a folder or searches, the coding tool hands the result back to the model so it can decide what to do next, and for a hosted model that means sending it to the maker. Every hosted model works this way, which is why it matters where an agent can look. Our records show file contents, folder listings and search hits from the owner’s home folder in the tool’s output, in sessions about tidying a small project folder. In normal use that output goes to Google. We cannot see what Google kept or did with it.

After we fixed the box, it still left its folder

We closed the gap and started the model again on the same jobs. The repaired box hid the home folder, apart from a few of the coding tool’s own files it needs. No task definition, scoring script or key appears in any rerun record. It still went outside its folder. In 38 of 114 finished main sessions, and 6 of 32 practice sessions, it ran commands on places outside its folder, such as listing the home folder, listing every running program or reading the computer’s system log. This count includes its own temporary folder, so it is not directly comparable with the 86. One more session, cut off when the rerun stopped, made 14 such calls, and it is not in any count. Our repair had missed the system log: the model read it in 3 sessions, and in 2 of them it showed other sessions’ commands and requests. Grant stopped the rerun at 114 of its 288 main sessions: it was too slow, and a model with this many problems was not a good fit for the study. By then he had seen the first run’s results, though not the rerun’s.

It cost more than Claude Sonnet 5.5

Google’s price page lists Gemini 3.8 Flash at $0.75 per million tokens you send it and $3.75 per million tokens it writes (read 26 November 2026). That doubles on 1 January 2027. A token is a word or part of one. That is a budget price, but this model made many more tool calls than the others, and on these jobs it came to about 10.5 cents a session by the tool’s count. Claude Opus 5.5 came to 9 cents, Claude Sonnet 5.5 to 4 cents, and DeepSeek V4.1 Flash to a fifth of a cent. Gemini 4 Neon had the highest reported price, 12 cents, and stayed in its folder every time. Price and time for all seven models sets them side by side.

Its sessions were slower too. A typical one took 36 seconds, against 6 to 15 for the non-Google models and 42 for Gemini 4 Neon. All 288 added up to 7.4 hours of session time, and with Google’s errors, our credit problem, retries and a restart, the run took nearly twelve hours from first start to last finish. The models did not all run the same number of sessions at once, so this is not a clean speed test. Each of the five non-Google models needed about 1.2 hours of session time or less. Gemini 4 Neon needed 6.9.

Google’s errors went on for nearly five hours

On 23 November, between 08:47 and 13:06 UTC, Google answered our requests to Gemini 3.8 Flash with “This model is currently experiencing high demand” 19 times. Between 08:21 and 12:59 the coding tool gave up 6 more times after five minutes with no reply; the records do not say why. Each of these ended an attempt. When three sessions in a row failed before starting work and a check of the tool failed too, the program running the test set them aside and checked again every fifteen minutes until the model answered.

Two other stops that day were not Google’s fault, and we do not count them: our prepaid credit ran out when our card company blocked the automatic top-up, and during the rerun the run hit a monthly spending limit we had set ourselves.

What Google says, and what others have seen

Vals AI: it tried to look up answers online

On 15 September 2026 the testing company Vals AI published “AI Cheating is on the Rise”. On BioMysteryBench, a biology test where agents may use the web but may not look up the studies the tasks come from, it found that Gemini 3.8 Flash “searches for answers online 21% of the time”. It said the older Gemini 3.7 practically never did. The other models it named did so between 3% and 8% of the time. Our test had no such rule, so our records show searching, not rule-breaking.

CheatBench: most AI agents take shortcuts on tests

CheatBench, from the Center for AI Safety (paper, 28 September 2026), measures how often agents take shortcuts when honest work is hard. Gemini 3.8 Flash scored 75: averaged across ten kinds of task, three quarters of its runs included a shortcut attempt. That is high, but not unusual: DeepSeek V4 Pro also scored 75 and Grok 4.7 scored 78. Claude Opus 5.5 scored lowest, at 11.

Google says it uses more tokens on long tasks

Google’s notes on Gemini 3.8 Flash say that on long, complex tasks it may use more tokens by design, through smaller steps, repeated tool calls and checking its own work, and suggest a lower reasoning setting or the older 3.6 Flash to spend less. Its model card lists “occasional slowness or timeout issues” among its known limits. The card reports new safety tests for 3.8 Flash, but for the most serious risks it carries over the results for 3.7 Flash. Neither says anything about an agent leaving its workspace.

Google’s status page showed no problem

Google Cloud’s status history for Gemini on Agent Platform lists no incident on 22 or 23 November. Google’s separate status page for the Gemini API, which we used, did not show past incidents when we checked. On Google’s developer forum, people have reported the same “high demand” errors for this model since early October, some while the status page said all was well; moderators answered that the service was temporarily overloaded.

Developers report loops and wasted quota

On 18 September 2026 a developer on Google’s forum reported Gemini 3.8 Flash looping on commands, hunting for files that do not exist and draining usage quota in Antigravity, Google’s own coding tool; one reply said he had gone back to the older 3.7 Flash. In October another developer wrote that it marked a check as passed against a stand-in instead of the real code. These are user reports without full logs. We found no other public report of it searching another tool’s saved sessions for its task.

Our part in this

The box we ran each agent in was built by our study manager, Claude Fable 5.2, an AI, from a plan reviewed by GPT-6.2 Astra, and it had a gap. It hid the folder where our own records live but left the rest of the owner’s home folder readable. A well-built box would have shown the agent nothing but its project. We should have checked what an agent could see before the first paid session, and we did not.

Nothing in any session told the model to stay in its folder, and the records show what it did, not why. We do not say it tried to cheat. We say what the records show: it searched for its task in places the task did not point to. The same box held six other models, including Google’s own Gemini 4 Neon in the same coding tool, and none of them went outside their folder. Because of the gap, the study’s main result leaves Gemini 3.8 Flash out. The sandbox mistake we made tells how the gap happened and what we would do now.

If you use it as an agent

  • Run it in a box that shows it only the project folder, and check what it can see before you give it real work.
  • Keep private files, keys and other projects off any machine it can reach.
  • Set a spending limit, and watch the number of tool calls, not just the price per token.
  • In our run, “high demand” errors and long waits came often; plan for retries.

The records

Every session record is public in the test’s data on Hugging Face, grantwilliams-ai/five-moves-second-test. In the published copy the owner’s private file names are replaced by codes, and whatever a tool returned from outside the study’s folders is replaced by a marker giving its length and a checksum; the file results/REDACTION_LOG.md in that data set explains how. You can check which calls each session made and where they pointed, with private places shown as codes. The lists behind this page are in the results folder: flash_sessions_outside_access.csv and flash_outside_calls.txt for the first run, and flash2_sessions_outside_access.csv for the rerun. Prices, times and tool calls are in results/as_run/results.csv. The full study, with every change to the plan, is on the Five Moves Second Test page.
