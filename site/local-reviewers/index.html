Measured study · one RTX 5090 desktop

Local models on one document job: best agent run 74.0, one script setup 100.0

The job: in a real 45-row project status table, move the done rows to an archive (only one row was done) and shorten the rest to 300 characters or fewer, without losing an open item or a link. On one RTX 5090 desktop, the best local agent run scored 74.0 of 100 (60.0 on its repeat), and one script setup scored 100.0: no mechanical penalties on this one table, not a grade of the writing.

In short
  • Send one row per call from a script, not the whole job to an agent. In the 100.0 setup, one row per call alone scored 52.0; a different model checking, then a plain-code fixer (a program with no model in it that trims rows, restores cut file paths and adds each row's record link), took it to 100.0. The same steps with one model writing and checking scored 81.0. What to do
  • Read 100.0 as "no points off, on this table". The best agent run wrongly archived one row (the one that can be read two ways) and lost two links; the 100.0 run archived only the done row and lost no link. The setup was tuned to this table. Limits
  • Use a local model as a second code reviewer, not the only one. In the four reviews both ran, one run each, GLM-5.3-Flash and DeepSeek V4 Flash stood out. Two other runs gave a wrong all-clear, and three runs, one of them GLM-5.3-Flash, called high-severity items sound. Reviews

01

What to do

  • Split a long job into one item per call, from a script, rather than handing it to an agent (a model that works through a task on its own, in a program that lets it read and write files). Validate each reply; retry with the exact complaint.
  • Have a different model check by quoting evidence, not giving a verdict; then fix mechanical slips with plain code, no model.
  • Switch thinking (a model's hidden reasoning) off for small per-item calls; cap it for long reviews. Send it in the request itself; do not trust the server default. The switches
  • Check your harness (the program that runs a model as an agent): read limits, output caps, sampling settings. Harness limits
  • Treat a local "all clear" as not yet an all clear, and a local alarm as a lead to check.
02

What we found

The job and how it was scored

A real status table of 45 project rows had to be sorted: live, finished with an open item, or done. Kept rows had to shrink to 300 characters or fewer, keeping open items and links; done rows moved to an archive word for word. Only one row was done, on our reading. Each attempt started at 100, less 15 per wrong archive (a row archived that still had open work), 5 per missing row, 3 per invented or mangled row, 2 per row over 300 characters, 1.5 per lost link, 1 per row kept that should have gone and 0.5 per untraceable open item. Scores can go below zero.

One row can honestly be read two ways; several good drafts lost 15 points there. A test draft with thirteen planted defects (5 dropped open items, 3 invented facts, 3 lost links, 2 wrong archives) scored 61.0: 2 wrong archives, 2 invented rows, 2 lost links. The dropped open items, one invented fact and one lost link did not change the score.

The same job, one row per call

On 10 October a script sent one row per call, checked for valid JSON (a structured text format) of the right shape and retried up to three times naming the fault. Rows still failing fell back to their last answer forced into the limits, or their original cell, flagged. A different model then had to quote, word for word, any open item in a row marked done, which sent the row back to be redone. Last, a no-model fixer (ordinary code) restored cut file paths, trimmed at word boundaries and appended record links.

Two earlier fixer versions, voided on 2026-10-10 for changing valid rows, scored 95.5 and 100.0; the published 100.0 is a later re-run.

"Extras" are real defects the frontier read of the same diff had not listed. Found-counts include partial matches, scored by the author. On the security change the frontier reviewers could also read the code base; one recorded two high-severity items, the other none. None of the four local reviews of the security change matched either in full. The locals saw only the diff, so that row is not like for like with the frontier reviews; both items turn on code outside the diff. On the tool diffs, the local and frontier reads used the same diff. A false pass is a defect called sound. Three other reviews logged on 10 October are left out because their jobs are private: one with 1 extra find, 1 miss and 1 false alarm in 8 minutes; one with 1 false pass and no misses in 39 seconds (the log's minute field: 1); one with 1 miss and 1 false alarm in 32 minutes.

GLM-5.3-Flash and DeepSeek V4 Flash stood out, and MiMo-V2.6-Flash-RL matched every reference defect once its thinking was capped. A reader who trusted MiniMax M2.7's confident all-clear, or Qwen3.8-27B's "No code changes required", alone would have acted on it.

What each model needed

  • Qwen3.8-27B: thinking off as an agent. Thinking on, it spent whole 32,000-token OpenCode steps thinking and made no edit, in three runs across two jobs. Send chat_template_kwargs: {"enable_thinking": false} with its non-thinking sampling settings (temperature 0.7, top_p 0.8, top_k 20). It then fixed both of two real defects; tests passed 53 of 53 (20 minutes by the test's note, 102 steps, 34 edits). A review found defects the tests missed; a second round (24 minutes) fixed five, and tests passed 70 of 70.
  • Qwen3.8-Flash-Next as a checker: thinking off. A checking call ran past 10 minutes with no answer; with the same switch, 6 to 30 seconds.
  • MiMo-V2.6-Flash-RL: cap thinking on the server. Uncapped, it spent all 24,000 tokens thinking and wrote nothing; with the server capping thinking at 14,000 tokens (--reasoning-budget 14000), out of 24,000 asked for in total, it wrote the 7-of-7 review.
  • Claude Code: a small proxy. The local server refused Claude Code's system message inside the message list with HTTP 500, "System message must be at the beginning". Moving it to the top-level system field fixed it: one tiny file in 2 turns, 39 seconds, on Qwen3.8-Flash-Next (not the document job).
  • Gemma 4 31B and 26B-A4B: send thinking on in the request. Without it: 0 reasoning characters. Thinking on, Gemma 4 31B fixed three of three first time; off, two of three eventually (one at first), and 26B-A4B one of three.
  • GLM-5.3-Flash has no thinking-off: effort is low, high or max.

Harness limits

  • OpenCode's read tool cuts lines over 2,000 characters; nine rows were longer, and a cloud agent spent 214 tool calls recovering the cut text, then timed out. Wrapping lines at 1,500 characters at most fixed it.
  • OpenCode sends no sampling settings, so a local model runs on whatever its server was started with.
  • OpenCode's config capped Laguna S 2.1 at 8,192 output tokens per step; raised to 32,768, it hit the harness maximum of 32,000, unfinished. Other answers needed about 14,000.
03

Limits

  • Most figures are one run of one model on one job. The one local agent run that was repeated (Qwen3.8-Flash-Next, same setup) moved from 74.0 to 60.0; the hosted table has a Grok retry and two GLM 5.3 runs. Two earlier fixer versions were voided; the 100.0 is a later re-run.
  • The 100.0 setup was tuned on the table it scored: checker and fixer were built after we saw which rows failed, and it is untried on a second job.
  • 100.0 is no mechanical penalty, not a prose grade. The weights are ours; the scorer did not catch 5 planted dropped open items, one planted invented fact and one planted lost link. Seven shortened rows read as usable, sometimes choppy.
  • Nothing here rules a model out; one that did badly on one job has only not been shown to do well.
