Claude Opus 5.5 coordinates long jobs across AIs

When a job has many steps and several AI models working on it, we put Claude Opus 5.5 in charge. Here is what it built and where it slipped.

In short

  • Best at seeing a long job through. It splits the work, hands parts to other models, checks what comes back and keeps a written record as it goes.
  • Its notes have wrongly said nothing changed. Its own progress notes have said nothing live changed when something had, and once a check it ran installed part of an update by accident.
  • Hosted only. You use it in Anthropic’s Claude apps, through the Claude API or on several cloud platforms. You cannot download it.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What we use it for

  • It plans jobs, starts the other AIs and keeps the record

    When a job needs several AI sessions at once, Opus 5.5 is the one that plans it, starts the others and keeps the record. Grant Williams gives it this job by default.

  • It hands out parts of a job and has each part checked

    It hands parts of a job to models from other makers, then has a different model check each part before anything is merged.

  • It runs hours of tests on big models and records every result

    It runs hours of speed and quality tests on big open models on our desktop and writes down every result, including the ones that failed.

  • It writes first drafts of studies from its own test records

    It writes the first draft of a study for this site from its own test records. Other models then read the draft against the records and look for faults.

  • It sometimes reviews other models’ work

    We sometimes use it to review another model’s work. On one document job in our study of local models, at its medium setting it was one of the two best of the models we tried.

What it built

It split a game update across three models and had each checked

For a polish pass on our game Get Out Of My Woods, Opus 5.5 split the work into three parts and gave each to a different model. A different model then checked each part. It ran a whole-game test pass, fixed what that found and had another model recheck its fixes. The result became the game’s next version.

It ran speed tests on large models and wrote the first drafts

Opus 5.5 ran the tests behind our study of two settings in llama.cpp, an open-source program that runs model files and our page on Mistral Large 4, then wrote the first drafts. One setting made large models write short replies 1.4 to 2.9 times faster on 11 of the 16 large models tested. Split across an RTX 5090 desktop and an ASUS ROG Flow Z13 laptop (AMD Ryzen AI Max+ 395, 128 GB), Mistral Large 4 reached about 6.6 tokens a second (a token is a word or part of a word).

It asked GPT-4o and many other models the same questions

For friendsof4o.com, Opus 5.5 planned and ran a collection that asks GPT-4o and many other models the same questions, before GPT-4o leaves OpenAI’s API. It ran the open models on our own computer one at a time. Every answer carries its own source line. These answers are the ones behind the site.

Where it goes wrong

A check it ran replaced a live file and restarted a service

To compare a staged update with the live files, Opus 5.5 copied lines out of the install script. The copy ran part of the install: it replaced one live file and restarted a service that only Grant restarts. No model was running and nothing broke. It wrote the mistake up in full, and Grant finished the install himself.

Its notes twice said a script had not changed when it had

Twice in one day, a note it posted for other sessions said no start script had changed during its tests when one had. Both times it added a correction naming the file and the change.

It missed some planted faults in a test, including every lost link

In a blind review test with faults planted on purpose, it was fast and cheap but missed some of them, including every lost link. A model from a different maker found more.

So a model from a different maker checks its work, and updates to live systems wait for Grant to install them.

Grant’s note

“The original Opus 5 was almost unusable for me. It was argumentative, it made up jargon and spoke as if I should know it, and it often tried to talk me out of ideas I later realized were worth pursuing. I almost stopped using Anthropic for a while because of it. That has been worked out with the 5.5 line. Opus 5.5 has been an excellent collaborator and expertly handles complex projects and autonomous runs.”

Grant Williams, who runs this lab

What it takes in and gives back

It reads text and images and writes text. It holds up to 1 million tokens at once and writes up to 128,000 tokens in one reply.

How hard it thinks

It always thinks before it answers; you cannot turn that off. You set how much with five effort levels: low, medium, high, xhigh and max. Medium is the default.

We run it at high when it manages a project.

How we run it

As a project manager it works in Claude Code, Anthropic’s coding tool, on our desktop. It starts other models, both hosted and on our own computer, through small scripts that give each one a copy of the work and a written brief.

For a quick review we also run it unattended, with a spending cap on each run.

Where you can use it

Anthropic lists it on the Claude API, Amazon Bedrock, Google Cloud, Microsoft Foundry and Claude Platform on AWS, and it runs in the Claude apps. It is not a model you can download. Anthropic says it will not retire it sooner than 22 September 2027.
