gpt-oss-120b is quick but weak working alone

OpenAI’s larger open-weights model runs fast on one desktop and passed our tool checks. Working alone on a real job it did badly, and its built-in chat rules have habits worth knowing.

In short

  • Quick for its size. With its experts in system memory and a small cache on the card, it wrote short replies at 85.24 tokens a second in our test. A token is a word or part of a word.
  • It did badly working alone and rarely asked questions back. On a real table job, working on its own through a coding program, step by step, it did very badly, and in chat it rarely asked a question back unless told to.
  • Download it free. OpenAI publishes it under Apache 2.0. We run Unsloth’s F16 file in llama.cpp.

Writing speed: fast. It wrote about 85 tokens a second (short replies on our desktop), so a 300-word answer takes about 5 seconds. The home models on this site run from about 1 to about 224 tokens a second. Compare them all.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What our tests showed

A newer setup sped up its short replies

With a newer llama.cpp build and a cache of experts on the card, short replies went from 34.58 to 85.24 tokens a second, and it read a 20,000-token prompt at 2,671.9 tokens a second.

It used memory tools correctly and found all planted codes

In our own checks it used memory tools correctly 15 of 15 times and found 3 of 3 codes we had planted in the text to see whether it could find them, about 106,000 tokens deep.

It asked no questions back unless a note told it to

Over 24 everyday answers with only a memory note, it asked the user a real question back 0 times. With a note asking it to, it did 21 times. Details are in our note study.

What to watch for

Working alone, it filed away 8 rows that still had open work

Asked to sort and shorten a large table through a coding agent, it archived (filed away as finished) 8 rows that still had open work and lost 6 links. Other local models struggled at this job too.

56% of its replies hit the length cap and were cut off

Through a hosted provider, with a 1,200-token reply cap, 56% of its replies with no system prompt hit the cap and were cut off.

It adds the date and silently drops mid-chat system messages

The chat template, the built-in rules for how a conversation is laid out for the model, writes its own opening message, including today’s date from the clock, so a long conversation is read again after midnight. A system message sent mid-conversation is silently dropped, and there is no thinking off switch.

When told to ask questions, it sometimes built them on facts that were not in the conversation, so we read its questions with care.

The facts

What do you need to run it?
ItemWhat we use
The fileUnsloth’s F16 file, 65.4 GB
The machineOne RTX 5090 graphics card (32 GB), with all experts (the parts a mixture-of-experts model picks from for each word) in system memory

Our older setup kept the experts of 23 layers in memory. In November it no longer loaded: the card ran out of memory while asking for 1,315.93 MiB more. Leave headroom on the card.

How do we run it?

In llama.cpp, the open-source program that runs model files, with OpenAI’s official chat template passed as a file and a 131,072-token window. OpenAI’s page recommends temperature 1.0 and top_p 1.0.

License, and where do you get it?

Apache 2.0, from OpenAI’s page on Hugging Face. OpenAI gives it 117B parameters with 5.1B active, and says it fits a single 80 GB graphics card.

We run Unsloth’s F16 file, with experts partly in system memory to fit a 32 GB card.

From OpenAI’s model page on Hugging Face, read 21 November 2026, and our own published measurements.
