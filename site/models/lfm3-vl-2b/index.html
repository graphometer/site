Pictures gave LFM3-VL-2B more answers and more mistakes

LFM3-VL-2B gave no answer on 20 of 48 runs with typed warehouse order slips. Pictures of the same slips started an answer every time and were faster, but made up four values in 20 runs on slips with unknown details.

In short

  • Pictures produced answers faster than typed text. LFM3-VL-2B started an answer on all 48 picture runs. On 20 of 48 typed runs it spent all its allowed reasoning space and wrote no answer. For runs that wrote something the typical wait was 30 seconds for pictures and 56 seconds for typed text.
  • Pictures brought more right answers and more wrong ones. From pictures 39 replies were complete records in JSON, a fixed format a program can read. Of these 31 were exactly right and eight had a wrong field. Typed slips produced 28 complete replies. Of these 27 were exactly right and one had a wrong field. LFM3-1.7B, the text-only comparison model, returned 34 exactly right answers from the same typed slips.
  • Pictures sometimes filled in unknown details. Five slips had a detail that should have stayed unknown. LFM3-VL-2B supplied a made-up value in four of 20 picture runs and none of 20 typed runs. Another four picture runs copied the slip’s question mark for unknown. That had the right meaning but the wrong format, so it was not counted as an invented value.

By Grant Williams, who runs Graphometer · Facts checked 27 November 2026

What our tests showed

Pictures won more matched pairs but not all of them

Across 48 matched pairs 20 were right both ways. Pictures alone were right in 11 pairs and typed text alone in seven. Both were wrong or missing in ten pairs.

Pictures helped with similar order numbers and later updates

On a slip with a second order whose number looked similar all four picture answers were right. Two typed answers were right. On another slip a later update settled a disagreement between earlier updates. All four picture answers were right and two typed answers were right.

Typed text won when updates were not in time order

One slip listed two updates out of time order. LFM3-VL-2B returned the right record on all four typed runs but only two of four picture runs.

What to watch for

Eight complete picture replies had a wrong field

Eight of 39 complete picture replies had a wrong field, against one of 28 complete typed replies. Four of those eight picture replies were wrong only because they used a question mark instead of null. Null is the JSON term for missing information. The typed error also used a question mark.

Pictures invented values that should have stayed unknown

LFM3-VL-2B invented a value in four of 20 picture runs on slips with an unknown field. It did so in none of the 20 typed runs. Another four picture runs used the slip’s question mark for unknown. Those answers had the right meaning but the wrong format. They do not count as invented values.

Eight other picture replies added extra words

These were separate from the eight complete replies with a wrong field. They added extra formatting or an explanation around the record although we asked for the record alone. A program expecting only JSON would reject them. Six contained the right three values despite the extra words. The other two each had a wrong value.

We did not test photographs or scans or any task beyond these warehouse order slips on one laptop.

The facts

What did we run?

We used 12 warehouse order slips. Each described an order and later updates. The task was to return the final order record as JSON. This is a fixed format a program can read. The record had three fields. Each slip was tried four times with different starting numbers for the model’s random choices.

LFM3-VL-2B received every slip as typed text and as a clean computer-made picture of the same text. The pictures had black type on white. They were not photographs or scans. Both versions used the same answer key. LFM3-1.7B is a text-only comparison model. It received the typed slips only.

What settings did we use?

The question and reply together had room for 8,192 tokens, which are the small pieces of text a model reads and writes. The model could use up to 4,096 of these tokens for its reasoning and final answer.

Program settingValueWhat it controls
Temperature0.4How freely the model chooses the next token
Top-p0.95How much of the total probability to keep
Top-k40The maximum number of choices
Min-p0A cutoff relative to the most likely choice

The first LFM3-1.7B attempt used a limit of 256 tokens per reply and covered only 26 runs. Every run used the full limit on reasoning and wrote no answer. That limit was far too small for these models. We discarded this incomplete attempt and repeated the full test with a limit of 4,096 tokens. None of the discarded runs appears in these results.

How often did a usable answer arrive?

Empty means the model used its full token limit on reasoning and wrote no answer. Cut off means an answer started but ran out of room. Extra words means extra formatting or an explanation surrounded the answer. Those replies fail the instruction to return only JSON. They do not count as complete or right.

JSON is a fixed format a program can read. A complete reply was one JSON record with the three requested fields and no extra words. Exactly right means all three fields matched the key. A complete reply with a wrong field had at least one value that did not match.

How did we score unknown values?

Five slips had at least one field that the answer key said was unknown. A concrete value there was an invented value. The slip used a question mark to mean unknown. A model that wrote that mark understood the meaning but used the wrong format. We scored it as wrong but not as an invented value.
