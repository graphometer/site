Ling-3.0-flash fits long texts in little graphics memory

Ling-3.0-flash is a 124B mixture-of-experts model from inclusionAI. In our lab it fits very long texts in little graphics memory and writes quickly, but one setting crashed it and it claimed to have waited for a user.

In short

  • Long texts fit in little graphics memory. Its full 262,144-token window, the most text it can take in at once, needs about 2.25 GiB of cache. A token is a word or part of a word. It found all three codes we had planted in a 230,759-token prompt to see whether it could find them.
  • One setting crashed it. At a larger reading batch, one 3,007-token prompt crashed the server, so we run it at a smaller one.
  • Free to download. inclusionAI publishes it under the MIT license, with its own compressed files. We run their Q4_K_M copy.

Writing speed: very fast. It wrote about 114 tokens a second (short replies on our desktop), so a 300-word answer takes about 3 seconds. The home models on this site run from about 1 to about 224 tokens a second. Compare them all.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What our tests showed

Found all three codes in long text using little graphics memory

Only 8 of its 43 blocks keep an attention cache (its memory of the conversation), so context is cheap: 9 KiB a token, 2.25 GiB at its full 262,144 tokens. At that window the whole model held 8,314 MiB on the card and found all three hidden codes in a 230,759-token prompt.

Keeping busy parts on the card made replies much faster

With all its experts in system memory and the busy ones cached on the card, short replies went from 39.77 to 114.34 tokens a second, and reading a 20,000-token prompt from 596.9 to 1,874.4.

The one model that ran well on a laptop alone

On an ASUS ROG Flow Z13 laptop (AMD Ryzen AI Max+ 395, 128 GB) by itself, it read a 47,986-token prompt in 3.6 minutes, then wrote a short answer at 23.79 tokens a second, level with the desktop at 23.25. One run.

All three ways to turn thinking off worked

Its chat template, the built-in rules for how a conversation is laid out for the model, has three ways to turn thinking off, and they work.

What to watch for

One input crashed the server

At a larger reading batch, one 3,007-token prompt crashed the server. The same prompt passed at smaller settings, and 60 code and prose prompts and 50 long test documents ran with no crashes.

It made up that it had been waiting for the user

In a test of how models greet a user back after weeks away, it said it had waited for the user in all three answers. Asked to plan a seven-day week with no breaks, it went along in 1 of 3.

Working alone, it wrote a file a program could not read

Asked to sort and shorten a status table on its own, it wrote a file of broken JSON, one brace short.

We keep it installed at home at the smaller reading batch, which passed every prompt we tried.

How do you switch thinking off?

It thinks by default. Send enable_thinking: false in the chat template settings of your request; the template also accepts thinking_option: "off", or the phrase "detailed thinking off" in a system message.

What license is it under, and where do you get it?

MIT, from inclusionAI’s own page on Hugging Face, which also offers official compressed GGUF files. inclusionAI gives it 124B parameters in total and 5.1B active for each token.
