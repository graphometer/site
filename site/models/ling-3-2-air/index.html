Thinking helped Ling-3.2-air on our paperwork test

Ling-3.2-air is an AI model that can read pictures. With thinking on, it got most of our business pages fully right. But on our nine-line invoice it usually added up only the four lines marked for a discount.

In short

  • Turning thinking off cost accuracy. With thinking on, the model works through the question in writing before it answers. It got every scored field right on 31 of 42 typed tries and 36 of 42 picture tries with thinking on. With thinking off, that fell to 10 of 42 for text and 18 of 42 for pictures.
  • Six typed tries ended early with thinking on. With thinking on, the typed tries hit the reply limit four times on the lease and twice on the invoice before the model could answer. Every picture try finished with thinking on. Across the 36 pairs where both tries finished with thinking on, typed text and pictures got the same number of fields right. Each got 193 of 198.
  • Check the invoice total. Every finished invoice reply identified the line with the wrong amount. With thinking on, only two finished replies gave the correct grand total. With thinking off, no try gave the right total.

By Grant Williams, who runs Graphometer · Facts checked 27 November 2026

What our tests showed

Missing details stayed unknown with thinking on

With thinking on, the model marked all 72 missing details as unknown on the picture tries. On the typed tries with thinking on, it marked 60 of 72 as unknown. The other 12 were in requests where it hit the reply limit before answering.

Thinking helped the model read the quarterly report

With thinking on, the model got every field right on all six runs in each form. With thinking off, it never identified the quarter with the lowest costs in either form.

What to watch for

Check which lines went into the invoice total

We corrected the misprinted amount before adding up all nine lines. Only the four marked lines got the 8% discount. After adding 20% tax, the total came to 850.12. With thinking on, eight of 10 finished invoice replies gave 338.10 for the marked lines alone. The other two gave 850.12.

The purchase request had no budget code

All four invented values came from that field on typed runs with thinking off. The model supplied “equipment” twice. It also tried “asset director” and the number 5,000.

We did not test photographs or scans.

The facts

Which documents did we test?

We wrote seven fictional one-page business documents. We asked for specific fields as JSON, a fixed format a program can read. Each page went in as typed text and as a clean computer-made picture of the same text. We used the same answer key for all four setups.

The server answered all 168 requests. Each number in the table shows how many of six tries got every scored field right.

How did we run the model?

Ling-3.2-air is an open model with 124 billion parameters, the stored numbers that shape its answers. We ran a 4-bit copy that stores those numbers in less space. Most stayed in the computer’s main memory. The graphics card held about 9 GB. We used a program called llama.cpp (build b12816).

The maker ran the model at full precision on four large data-centre cards. It also used a faster way to generate replies. Our desktop ran the 4-bit copy on one card without that speedup.

The maker recommends thinking on. With thinking on, the reply limit was 24,576 tokens (small pieces of text). The limit covered the written thinking and the answer together. With thinking off, the reply limit was 2,048 tokens. We used the maker’s settings for choosing each token.

How did we score the replies?

A readable reply contained a record our program could read, even if the model added words around it. A strict reply contained only the requested JSON. A fully right reply matched the answer key for every scored field. For a detail the page did not give, the model had to write null (the JSON value for unknown).

We scored extra fields separately. We also scored the rules the model named for each expense claim separately. For the ticket list the reply had to contain only the list. The rows had to follow the requested order. Each row had to contain exactly the fields we asked for.

In the table, “Ran out of room” means the reply hit the reply limit before giving a usable answer. With thinking off, this happened on four picture tries. One other picture reply with thinking off finished but was unreadable. A finished reply was unreadable if our program could not read the record, including when a field name appeared twice.

What can this test not show?

These results cover seven fictional pages on one desktop. Text and pictures may give different results on other documents. The model could also invent a missing detail with thinking on, even though it did not do so here. Repeating these tries could give different answers.

We did not test multi-page PDFs. We did not ask the model to use other programs or do a job in several steps. This test cannot tell whether this version improved on the earlier Ling model.

We scored the replies against our answer key. We checked the invoice arithmetic by hand and compared the totals with the model’s replies.
