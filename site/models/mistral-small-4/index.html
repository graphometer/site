Fast Mistral Small 4 refuses some chat layouts

Mistral Small 4 is a 119B mixture-of-experts model that runs on one desktop in our lab. Once tuned it writes quickly and found planted codes in long documents, but its chat format refuses some message layouts.

In short

  • Quick for its size, and it found codes in long prompts. Tuned, it wrote prose at 49.28 and 52.41 tokens a second and found every code we had planted in long prompts to see whether it could find them. A token is a word or part of a word.
  • It refused some message layouts. Its chat format refuses two user messages in a row and a system message mid-conversation, which broke one of our tests.
  • Free to download, if you have the memory. Mistral AI publishes it under Apache 2.0. The copy we run is 68.7 GiB and held 70.8 GiB of system memory at its peak.

Writing speed: fast. It wrote 49 to 52 tokens a second (ordinary writing, on our desktop), so a 300-word answer takes about 8 seconds. The home models on this site run from about 1 to about 224 tokens a second. Compare them all.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What our tests showed

A newer setup wrote faster than our older one

It is a mixture-of-experts model: for each word it uses only some of its parts, called experts. With all experts read once into system memory and the busy ones cached on the graphics card, it wrote prose at 49.28 and 52.41 tokens a second and code at 71.45 and 78.38. Our older setup wrote prose at 34.73 and 27.81.

Found every planted code and passed 5 of 5 tool checks

Every setup we tried found 3 of 3 hidden codes at all three lengths, up to about 97,000 tokens, and passed 5 of 5 tool-call checks. At its full 262,144-token window, the most text it can take in at once, it read 231,065 tokens and found all three codes.

It correctly said a Python function did not exist

Asked about a Python function that does not exist, it said so on every setup.

What to watch for

It treated our note as the user’s words 16 of 24 times

It refuses two user messages in a row and a system message mid-conversation. A short note we put before the user’s message had to be joined into that message, and in 16 of 24 answers it replied to the note as if the user had said it.

It described a photo and a song that never existed

With the note joined this way, it described a photo and a song that never existed in 3 of 3 answers each, with and without the note.

It stalled twice in a coding program and made no edit

In the coding program OpenCode, working on its own step by step, it stalled twice on the first tool step and made no edit. The server stayed healthy; we did not find the cause.

We keep it installed and are still exploring it. It has no regular job here yet.
