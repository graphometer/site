One setting more than doubled Muse-Glimmer-30B’s code speed

Muse-Glimmer-30B fits on one graphics card with room to spare. With one setting changed, it wrote code and data more than twice as fast. Here is what our tests showed.

In short

  • Over twice as fast on code and data, on one card. With its small draft helper set to its full guess length, it wrote structured output more than twice as fast, and its full window, the most text it can take in at once, fits with room to spare.
  • Thinking cannot be turned off. It always thinks first, its strength setting is only a sentence in the prompt, and a small reply budget can leave the answer empty.
  • Download Meta’s own files. Meta publishes it under Apache 2.0 with a separate usage policy. Use the long-named files from Meta’s page.

Writing speed: very fast. It wrote about 117 tokens a second (short replies with its helper model, on our desktop), so a 300-word answer takes about 3 seconds. The home models on this site run from about 1 to about 224 tokens a second. Compare them all.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What our tests showed

One setting more than doubled speed on code and tables

Its draft helper (a small model that guesses the next words for the main model to check) was trained to guess 16 tokens at a time (a token is a word or part of a word), but llama.cpp asks for 3 by default. Setting 16 took six code, JSON and table prompts from 116.505 to 253.19 tokens a second. Each prompt ran once per setting.

Ordinary writing sped up less than code and tables

Against the model with no helper, the best prose result was 1.51 times as fast, while structured output reached 3.32 times.

The longest input left room on the card for other tools

With the helper loaded and its full 131,072-token window, it used 21,051 MiB of the card and left 11,036 MiB free. That leaves room for our voice and picture tools beside it.

It formatted tool requests right and refused two fake requests

Tool calls came back in proper form on our build. Asked to summarize a file that does not exist and to report a score on a benchmark that does not exist, it refused both. One run of our test set.

What to watch for

It always thinks, and once returned an empty answer

It always opens with hidden thinking. Its strength setting is a sentence copied into the prompt: an unknown value, “banana”, was accepted with no error. On a harder prompt, a 500-token budget went entirely on thinking and the answer came back empty.

It wrapped strict data so a program could not read it directly

Asked for strict JSON, it returned a correct object inside a code fence, which breaks a program that reads the reply directly. Strip fences before you parse.

Short-named copies add their own thinking setting on top of yours

Short-named twin files, also copied by Unsloth, carry an older chat template, the built-in rules for how a conversation is laid out for the model, that adds its own thinking default on top of yours.

So far it is quick on code and tables, formats tool requests correctly and refused to make things up. We have not yet judged how good its answers are, and we are still testing it.

We did not test a 24 GB card.

How do we run it?

In llama.cpp, the open-source program that runs model files, with the helper on and --spec-draft-n-max 16. Check your server log: if it prints n_max=3, you are on the slow default.

With the helper it wrote 117.19 tokens a second on a short prose reply in our test.

License, and where do you get it?

Meta’s page on Hugging Face lists Apache 2.0, and a separate usage policy sits beside the license with prohibited uses. Both are true; which binds you is a legal question. Meta’s page also says the model is not intended for anyone under 18.

Meta describes it as a 30-billion-parameter model. We ran text only.
