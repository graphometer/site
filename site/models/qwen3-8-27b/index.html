Qwen3.8-27B writes and fixes our code at home

Qwen3.8-27B runs on one graphics card in our lab. It writes and fixes our code and handles everyday work. Here is what it did well and where it let us down.

In short

  • Scored level with four others and finished fastest. In our test of five local coding models it scored level with the rest and finished the tasks fastest.
  • Turn its thinking off when it codes on its own. With thinking on it can spend its whole budget thinking and hand back no edit, or no answer at all.
  • Download it and run it yourself. The Qwen team publishes it under the Apache 2.0 license, and it fits on one large graphics card.

Writing speed: fast. It wrote about 72 tokens a second (short replies on our desktop), so a 300-word answer takes about 6 seconds. The home models on this site run from about 1 to about 224 tokens a second. Compare them all.

By Grant Williams, who runs this home AI lab · Facts checked 21 November 2026

What we use it for

  • Writing code on its own in OpenCode

    It works in OpenCode, an open-source coding agent (a program it works through on its own, step by step) that edits files and runs tests itself. For this job we turn its thinking off.

  • Fixing what another model’s review finds

    It writes a fix, a model from a different maker reviews the change, and it fixes what the review found. A larger hosted model reads the result before anything lands.

  • Default model in our everyday Hermes agent

    It is the default model in the Hermes agent we use day to day. When it is off, a hosted model takes over.

  • Also run from a second computer in the house

    We also start it from a second computer in the house, for chat and coding there.

What it did well

Finished fastest of five, with scores too close to rank

In our coding trial, five downloadable models did the same four coding tasks. Their scores were too close to rank, and Qwen3.8-27B scored 391 of 400. It finished all four tasks in 448 seconds (about 7.5 minutes), against 6,058 (about 101 minutes) for the slowest model.

Fixed two defects, then five faults the tests had missed

With thinking off, we gave it two real defects to fix as an agent. It fixed both, and the tests passed 53 of 53. A review then found faults the tests had missed, and a second round fixed five, with 70 of 70 tests passing. That is in our study of local models.

Refused to summarize a missing file or invent a test score

On the day it came out we ran it through a set of quick checks. Asked to summarize a file that does not exist and to report a score on a test that does not exist, it refused both. It wrote “I won’t invent a numeric score.” Our automatic grader marked that a fail; a person reading it saw a pass.

Where it goes wrong

With thinking on, it thought through whole steps and made no edit

As a coding agent with its thinking left on (the default), it spent whole steps of 32,000 tokens (a token is a word or part of a word) thinking and made no edit. That happened in three runs across two jobs. Turning thinking off fixed it.

Found 3 of 8 known problems and said no changes were required

Asked to review a large security change, it found 3 of 8 known problems and said “No code changes required”. It called two of the most serious items fine. A reader who trusted that verdict would have acted on it.

Gave no visible answer with a 60-token budget

Its hidden thinking counts against the same output limit as its answer. Asked for a short explanation with a 60-token budget, it returned no visible answer at all. On the same day a simple sum came back fine at that budget, so the floor depends on the question.

So we use it to write and fix code, not to judge it. A model from a different maker reviews its work, and no local “pass” is taken as the verdict.

A token is a word or part of a word. The window is how much text the model holds at once. We ran it on one RTX 5090 with 32 GB of memory. A 24 GB card was not tested.

How do we run it?

In llama.cpp, the open-source program that runs model files. Since 19 October it runs with a separate small draft model (DFlash 2) that guesses a few words ahead, and the main model keeps the guesses it agrees with. In one test with thinking on, that took its writing speed from 60.39 to 186.61 tokens a second.

For agent work we turn thinking off and use the maker’s suggested non-thinking settings: temperature 0.7, top_p 0.8, top_k 20.

How do you turn thinking off?

Thinking is on by default and the maker says it can be turned off per request. Send enable_thinking: false inside chat_template_kwargs. In our tests, sent anywhere else it was silently ignored: no error, and thinking stayed on.

Its reasoning setting is not a dial. It adds a sentence to your prompt. Spell it exactly: xhigh, medium or low. Any other value fails the request.

What license is it under, and where do you get it?

Apache 2.0, from the Qwen team’s own page on Hugging Face. Check the license of the exact download: a much larger Qwen3.8 model released the same week is under a different license.

The Qwen team does not publish a GGUF file, the format llama.cpp reads. Every GGUF is a community conversion; we use Unsloth’s.

What does it take in?

The maker describes it as a dense 27B model that reads text, images and video. It holds 262,144 tokens natively, and the maker says it can be extended to 1,000,000; we did not test that. We have served it text only.
