Model field card · one RTX 5090 desktop

Qwen3.8-27B at 256K context on one RTX 5090: Q4 with MTP wrote faster than Q5 without it, Q5 stayed closer to the reference

At a 262,144-token window on one RTX 5090, Q4_K_XL with MTP on wrote structured replies (thinking off) at 144.7 tokens a second about 20K tokens deep, against 60.7 for the larger Q5_K_XL with MTP off, which matched an 8-bit reference slightly more often on one text, in single runs.

In short
  • For speed, run Q4_K_XL with MTP on. MTP (multi-token prediction) is built into these files: it guesses tokens (word pieces) for the model to check. Settings
  • For the closest match to the 8-bit reference, run Q5_K_XL with MTP off. With MTP on, its MTP part would not start beside the 8-bit cache at this window, in both attempts. Q5_K_S with MTP sits in between, with only 664 MiB spare.
  • Or give Q5_K_XL a separate small draft model, at a slightly smaller window (229,376 tokens). Since October, in one reasoning test (thinking on) it wrote 186.61 tokens a second, against 60.39 without. Results

By Grant Williams · Published 26 September 2026

01

What to do

Closest to the reference: Q5_K_XL with MTP off. Measured command; q8_0 is an 8-bit cache, the memory holding text read so far. Set your own local address:

llama-server --model Qwen3.8-27B-UD-Q5_K_XL.gguf \
  --jinja --ctx-size 262144 --parallel 1 \
  --batch-size 2048 --ubatch-size 512 \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --n-gpu-layers 999 --threads 24 --threads-batch 24 \
  --flash-attn on --temp 1.0 --top-p 0.95 --top-k 20 --min-p 0.0

For speed: Q4_K_XL with MTP on. Change the model filename and add these flags. They also serve Q5_K_S: closer to the reference than Q4_K_XL, and the same revision as the reference.

--spec-type draft-mtp --spec-draft-n-max 6 --spec-draft-p-min 0.75 \
--cache-type-k-draft q8_0 --cache-type-v-draft q8_0

If 128K (131,072 tokens) is enough: Q5_K_XL with MTP on, the faster baseline. Use both blocks above minus every cache-type flag, and set --ctx-size 131072.

Since 19 October: Q5_K_XL with a separate draft model, DFlash 2 for Qwen3.8-27B (a Q4_K_M file of 1.1 GB) plus n-gram drafting (guessing from text already seen), on the main llama.cpp version with -ub 256, an 8-bit cache, built-in MTP off and a 229,376-token window.

Keep the confidence gate (--spec-draft-p-min) explicit (why). -ub is the micro-batch, prompt tokens read at a time (more).

The long read and the crash check

At the 262,144-token window, each of the three files read a 229,152-token prompt and returned all 3 hidden codes, placed at about 5%, 50% and 95% of the ledger (not exact positions).

Crash check: Q5_K_XL without MTP and Q4_K_XL with MTP each completed 40 of 40 shorter mixed-text prompts at the 256K setting, each with a follow-up turn, with no crashes or empty answers. Q5_K_S was not crash-checked.

Why Q5_K_XL could not use MTP at 256K

In both attempts (--ubatch-size 256), the card refused these memory requests while setting up MTP:

Failed CUDA allocations during MTP setup
Draft cacheFailed bufferBytes
f161,024.00 MiB, KV cache1,073,741,824

These are the sizes requested, not how far short the card was. Q4_K_XL and Q5_K_S loaded MTP with 8-bit draft caches at --ubatch-size 512. Two failures do not show that every other Q5_K_XL setup fails.

Since October: a separate draft model

With thinking on, Q5_K_XL with DFlash 2 plus n-gram drafting wrote 3,500 tokens of reasoning at 186.61 tokens a second about 20,000 tokens deep, against 60.39 without the draft model; at 262,144 the same reasoning ran at 189.26. On a plain letter with thinking off the gain was 30 to 44 percent. Reading was 10 to 15 percent slower.

03

Limits

  • Single runs, no confidence intervals: small gaps, such as Q5_K_S against Q4_K_XL on prose, are not a stable ranking.
  • Speed is not answer quality. The letters and structured replies are controlled shapes, not a coding or tool-use test.
  • Two changes at once. Q4_K_XL with MTP against Q5_K_XL without changes both file and MTP. The 128K rows also differ in cache, so they isolate neither window size nor MTP.
  • Narrow fidelity test: one public technical text, against an 8-bit reference rather than full-precision weights. Q5_K_XL is an older upload, so differences cannot be credited to compression alone. The October setup was not re-scored.
  • Finding codes is not reasoning. One long read and a short crash check do not show reliable reasoning over a full window.
  • Same name, different file. The data package's expected-size list names another UD-Q5_K_XL of 20,876,938,144 bytes (stated), not tested; these memory results do not apply to it.
