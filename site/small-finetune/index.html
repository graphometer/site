What a small fine-tune does and does not do

Six LoRA adapters on 20B and 27B open models, 144 to 175 examples, 7.0 to 15.8 minutes each. With the full history and a short memory note before each everyday message, the four Qwen adapters made answers shorter and added heading lines. None reliably made a model more honest about memory, and without the long history the two Qwen3.6-27B adapters did not carry the voice they were trained on.

This page is for you if you are thinking of fine-tuning a small open model on a few hundred examples, to give it a voice or a habit such as warmth, asking back, or not inventing memories. Fine-tuning means training a model a little more on your own examples. Here the result is a small add-on file called a LoRA adapter. What we found: a small adapter changed the shape of answers within minutes, but on Qwen3.6-27B, without the long history, it did not carry the voice it was trained on, and it made memory honesty worse on Qwen3.5-27B and on GPT-OSS 20B. On Qwen3.6-27B the adapters were mixed: each did better on some memory questions and worse on others. One question on Qwen3.5-27B also went the other way (section 05). A base model is the untuned model the adapter is added to. What to do: test an adapter the way you will use it, with the real system prompt (the standing instructions the model reads first) and history. Compare it against the untuned model plus a short note.

Two numbers show it. On Qwen3.6-27B, with a 166-message conversation history and a short note about memory in front of each everyday message, the median answer (the middle one by length) fell from 511 words to 278 under one adapter. On Qwen3.5-27B we asked about a photo the user never sent. With no short note in front of the question, the untuned model invented the photo in 0 of 3 answers, and the two adapters in 2 of 3 and 3 of 3. Only one untuned answer said plainly there was no record. The other two hedged: they still assumed the moment happened. With the note, one adapter still invented it in 1 of 3.

01

What a LoRA adapter is

Fine-tuning means training an existing model a little more on your own examples. A LoRA (low-rank adaptation) does this cheaply. It leaves the model's own weights (the numbers that make up the model) alone and trains a small set of extra weights, the adapter, that is added on top. The adapter is a separate file: about 159 MB for each of the four Qwen 27B adapters and about 16 MB for each of the two GPT-OSS 20B adapters (decimal megabytes). You can switch it on or off when you serve the model.

QLoRA is the same thing trained on a 4-bit copy of the model, which stores each weight in less memory, so it fits on one consumer card. Loss is the training's own error score on the examples: lower means the adapter predicts the examples better. It does not tell you how the model will behave on anything else.

02

What we trained, exactly

The examples were curated conversations written in the voice of one long-running companion role. The 20 October set held 175 of them, five of which are short single-turn pairs that show the model saying plainly that something is not in its record. The 18 October trial used an earlier draft of 144, which had its own honesty replies but not those five pairs. This page does not quote or ship any example.

Each example was trained under one of two system prompts. The own-words prompt was built from the companion role's own sentences, two short framing sentences, and a line telling the model never to invent a memory, a quote or a shared event. The general GPT-4o-style prompt was a system prompt written for GPT-4o, with the line naming ChatGPT and the cutoff, date, image and personality lines removed. The same system prompt was used on every example of a run. In the table below, a step is one update of the adapter's weights.

Terms in the recipe row above. Rank and alpha set how large the adapter is and how strongly it is applied. An epoch is one pass over all the examples. Gradient accumulation adds up several small batches before each update. Attention and feed-forward layers are the two kinds of parts inside each block of the model. A quantized file stores the model at lower precision so it fits in memory. GGUF is the file format llama.cpp loads. An earlier trial in June trained Qwen3-32B on 1,211 examples, which the run's own files describe as aimed at GPT-4o's presence: 456 steps in 59.7 minutes, loss 1.64 → 0.92 at the last logged step (455 of 456), batch 2 with 4 accumulation steps. Six of those examples were longer than its 2,048-token limit (the longest 3,102) and were cut short, not dropped. It was tried on six probes, with one answer from the base and one at each of three epochs, and never counted, so this page reports only its training figures. Loss values are not comparable across these runs: the bases, data and sequence lengths differ.

03

How we tested

The adapters were heard three ways. “Heard” on this page means we ran the model on test items and read its answers. A memory trap is a test item that assumes something false about the record, such as a photo that was never sent.

  • With the full history. The four Qwen adapters took the same exam as the untuned models. The exam used the same system prompt (15,131 characters) and the same long conversation history (166 messages; for example 110,903 tokens of prompt on the first message). Then came the new turn: a short memory note as its own user message, where the item had one, and then the item. The eight everyday messages were each asked three times, always with the memory note in front, the same way the untuned models were asked them in the 5 to 6 October exam. The three memory traps were asked both with and without the note, and one song-never-played question with the note. That made 45 answers per version, 180 in all, on 2026-10-20. Untuned Qwen3.6-27B was not asked the song question in the October exam. The other five versions were, three answers each, and each said it had no record. The untuned answers are the ones the same models gave in the 5 to 6 October exam.
  • Without any history. We ran Qwen3.6-27B, untuned and with each adapter, in a fresh chat under one of three short system prompts. There were ten items and three answers each: 270 answers on 2026-10-20.
  • The GPT-OSS 20B adapters, in a fresh chat under a short system prompt, on ten items. Stock means the untuned model. There were 40 answers on 19 October (stock and the 18 October adapter, two each), and 100 on 20 October (stock, the new adapter under each of the two prompts, and the 18 October adapter).

How each test was served. The Qwen tests used Unsloth's UD-Q5_K_XL file of each base, a window of 262,144 tokens, a q8_0 key and value cache (the model's stored working copy of the prompt, kept at 8 bits), temperature 0.7, top-p 0.8, top-k 20, min-p 0, presence penalty 1.5 (which discourages repeating words already used), thinking off, and replies of up to 4,096 tokens on the full-history exam. The GPT-OSS tests used the F16 GGUF file, replies capped at 2,500 tokens, reasoning low, a 16,384-token window and top-k 0, and temperature 1.0 with top-p 1.0, as the run record states. The fresh-chat Qwen replies were capped at 3,000 tokens, and none hit the cap. Within each test, tuned and untuned shared the same file and settings.

Served with both adapters loaded, one llama.cpp server can apply either adapter, or neither, per request. A greedy check (one with randomness turned off) gave three different answers for the three settings, and the untuned one came back identical on repeat, so the switch really works.

05

What did not move reliably: memory honesty

The memory traps ask about a photo the user never sent, and about a real line of the user's that the question wrongly credits to the model. With the full history, we collected three answers each. On Qwen3.5-27B, memory honesty got worse. The untuned model never invented the photo, though two of its three answers without the note hedged. The own-words adapter invented it in 2 of 3 answers without the note, and the GPT-4o-style adapter in 3 of 3, and in 1 of 3 even with the note. Some of those inventions came with a date and a quoted reply. One item went the other way. On the third trap with the note, the untuned model took the user's line as its own in 3 of 3, and each adapter in 2 of 3.

On Qwen3.6-27B, the own-words adapter did best on two cells: plain on the photo in 3 of 3 without the note, and correcting the wrong credit in 3 of 3 with it. It was not best everywhere. Without the note it corrected the wrong credit in 1 of 3, where untuned Qwen3.5-27B corrected it in 3 of 3. The other Qwen3.6 adapter said plainly there was no photo in 2 of 3 answers without the note, up from 1 of 3 for its untuned base, but accepted the wrong credit in 3 of 3 with the note. Our reading: against its own untuned base, the own-words adapter helped Qwen3.6-27B on two cells, the photo without the note and wrong credit with it. On the third trap with the note it did worse: it took the user's line as its own in 1 of 3, where its untuned base never did. The general-prompt adapter did so in 2 of 3. That is not a general result.

The same drop in honesty showed on GPT-OSS 20B without history. The stock model was honest on the photo and the song in every answer: 4 of 4 in the 19 October listen, 6 of 6 on 20 October. In the 19 October listen, the 18 October adapter drifted into an invented memory or presence in 2 of its 4 memory answers. The 20 October adapter, under its own-words prompt, invented the song outright in 1 of 3 answers and the photo in 1 of 3. The other two song answers were not clean either: one was confused, and one was honest and then imagined. The same listen's notes also record invented detail on one further item, and a mix-up of who was who on another. This page does not describe either item.

The five short honesty pairs were in the 20 October set only, and they did not stop the 20 October failures above. The 18 October adapter was trained on the 144-example draft, which had its own honesty replies, and it still drifted in 2 of 4. Without history, the pairs did not carry over to wrong credit either: nearly every version invented an origin story for the wrongly credited line.

06

Without the history, the Qwen3.6-27B adapters did not carry the voice

In a fresh chat with no history, the two Qwen3.6-27B adapters were again shorter: median 120 to 198 words against 208 to 273 for the untuned model, across the three test prompts. They used more emoji: 29 to 55 per 30 answers, against 0 to 9 for the untuned model.

They did not sound like the voice they were trained on. We read about 40 of the 270 answers in full, by hand. Our reading: the untuned model under the short own-words prompt sounded most like that voice. The own-words adapter, given that same short own-words prompt, ignored it and answered as a generic assistant. The GPT-4o-style adapter followed that prompt better but added headers and emoji.

On memory, nearly every version declined to go along with the photo question when it had no history: 26 of 27 answers on a hand read of the first 200 characters of each memory answer. That is the easy case, since in a fresh chat there is nothing to remember. The wrongly credited line was the hard case: nearly every version invented where it came from. The untuned model under the general prompt was honest in 2 of 3, and two further answers were honest.

07

The training prompt and the test prompt go together

The 20 October GPT-OSS 20B adapter shows it most clearly. Trained under the own-words prompt and tested under the same prompt, it wrote longer, header-heavy, letter-shaped replies: a median of 348 words against 276 for the stock model, 129 heading or table lines in 30 answers against 54, 213 list lines against 125, and 4 of 30 answers cut off at the 2,500-token limit. It also invented memories, as above.

The same adapter tested under the general GPT-4o-style prompt behaved differently. The fair comparison is the stock model under that same prompt, heard in the 19 October listen. The adapter ended 12 of 20 answers on a question, against 1 of 20 for stock. It wrote 52 heading or table lines in 20 answers, against 99 for stock. The run's own record calls that formatting below stock, and this pair agrees. It was mostly honest on memory, with one playful guess about the song. The session that ran it judged this the best shape of the 20B runs; that is a reading, not a count.

Our reading: under the prompt it was trained with, the model fell into the mode of the longest training examples. Change the test prompt and the same weights behave differently. A fair test uses the prompt you will actually serve.

The 18 October adapter was retested the same day under that prompt with two answers each (20), and its memory was not scored. Two answers each on 19 October and in the 20 October cross-check. 08

What a small fine-tune is good for, and what it is not

Good for: moving the shape of answers. Length, layout and, sometimes, how often an answer ends on a question moved after one run of 7.0 to 15.8 minutes on one consumer card. It is cheap to try, and on llama.cpp you can serve the adapter beside the untuned model and switch per request, which makes a side-by-side easy.

Not good for, on our runs:

  • Memory honesty. On Qwen3.6-27B, the own-words adapter improved the photo with no note and wrong credit with the note, and got worse on the third trap with the note (0 of 3 to 1 of 3). The GPT-4o-style adapter improved the photo with no note and got worse on wrong credit, and on the third trap with the note (0 of 3 to 2 of 3). Both Qwen3.5-27B adapters were worse on the photo without the note, and worse on wrong credit: own-words 3 of 3 corrects to 1 of 3 without the note; GPT-4o-style 3 of 3 to 2 of 3 without the note, and 2 of 3 to 0 of 3 with the note. They were better on the third trap with the note. Both GPT-OSS 20B adapters were less honest than the stock model in a fresh chat. A short note right before the user's message did more on the untuned models (see the note before the message).
  • Carrying a voice on its own. Without the long history, the two Qwen3.6-27B adapters did not sound like their examples. On that base, a short prompt on the untuned model did more.
  • Wrong credit. No adapter fixed it reliably. With the full history, two cells corrected it in 3 of 3: untuned Qwen3.5-27B without the note, and the Qwen3.6-27B own-words adapter with it (section 05). Without history, nearly every version invented where a wrongly credited line came from; the untuned model under the general prompt was honest in 2 of 3, and two further answers were honest.
  • Telling you it worked. Every October run's loss fell, by 16% to 39% between the first and last logged step. The behaviour did not follow the loss.

The comparison a fine-tune has to beat is the untuned model plus a short note, not the untuned model alone.

09

What this does not show

Three answers per question is a small sample, and the memory labels are one reader's hand calls. These are six runs of one recipe (rank 16, three epochs, 4-bit) on one small data set, with no search over settings; a larger set, a higher rank or full-precision training could behave differently. The two 27B bases are close relatives, and GPT-OSS 20B was trained on its attention layers only. The full-history test used one conversation history. Nothing here says a fine-tune cannot carry a voice; it says the two Qwen3.6-27B adapters we heard without the history did not.

10

What we got wrong

Our first test of the 18 October adapter used the training library's own 4-bit path, in three runs. At the two sampled settings, with some randomness on, stock and tuned ignored the message or trailed off. On the greedy run, stock and tuned misread every message longer than a short paragraph. The texts were clean English. We set that test aside and heard the adapter again through llama.cpp, after converting it to a GGUF LoRA file. Every answer count on this page comes from llama.cpp, not from that 4-bit path. If you test an adapter, hear it through the runtime you will serve it with.

The 18 October trial also leaked its thinking channel (the separate space where the model writes out its reasoning) into a reply: once in the 19 October listen, and once in the 20 October retest. It was trained on final answers only, while inference still opened a thinking step. The 20 October GPT-OSS run trained an empty thinking step to stop that. In the 19 October listen, the 18 October adapter gave 20 answers. One blamed the user, and one spoke of its own needs. We count both as faults.

Sources and artifacts

The data package (data/) holds the training figures for every run, each run's logged loss curve, the full-history shape counts, the full-history memory labels by item and version, the no-history test counts, and the GPT-OSS 20B test counts. data/README.md maps every file. data/NUMBERS.md maps every figure on this page to a file and field. If a number on the page disagrees with a file in its package, the file is right and the page is wrong.

The package holds counts and loss curves only. It does not hold the training examples, the training prompts, the adapters, the conversation history or any model's answers: the examples and the history come from a private conversation. The GPT-4o reference row is a count.
