Graphometer Workbench
for Grok Build

See what Grok Build is doing, and stay in control.

A local, readable window on the Grok Build coding agent, for people who direct AI agents without living in a terminal. It puts the agent's sessions, its work as it happens, and every moment it stops to ask you a question into one plain screen.

01-05

What it does, shown in the film

Five capabilities, each demonstrated on screen. A measured note or the payoff under each one is the limit or the design decision behind it.

01

It asks before it changes your files

Permission cards, written in the agent's own words. In Ask mode, the Workbench shows the agent's own options and relays no approval until you pick one. The agent, not the Workbench, then writes the file. You see exactly what it wants to do before it does it.

Auto-approve exists, and it is honest too: one clearly labelled switch, confirmed on the way on, applying to every session in the window. Until you flip it, every request is a card in front of you, and the Workbench never invents a button.
02

Review and undo, one change at a time

Every changed file, with real plus-added and minus-removed counts, expandable to the full before-and-after. Undo any single change.

The Workbench's single-change undo leaves edits you made yourself untouched. Your work stays yours.
03

A context meter that adds up

The segments genuinely add up to the window. The meter reads what the agent reports, or it shows nothing at all.

A live mid-turn tick was built, measured wrong on the wire, and removed. A number the Workbench cannot stand behind is a number it does not display.
04

It survives the agent dying

Kill the agent mid-turn and the page says the agent process is gone, then reloads every session from the files on your machine and marks it recovered.

Never a blank page; never a recovery it cannot verify.
05

Every session in one sidebar

All your sessions grouped by folder, several live at once on a single agent. Rename them, organize them, and move between them without losing your place.

One window for all of it, instead of one terminal tab per thing you started.
06-08

And more

Beyond the film, the same discipline: say only what is true, and refuse visibly rather than guess.

Answer in the agent's own words

Permission, plan-approval and question cards use the agent's own option labels, verbatim. If it offers no options, the app refuses visibly rather than inventing one.

Reach for a file, not a path

Browse for a file instead of typing its path, open new sessions, and export or import whole sessions when you need to move them.

Shows the agent's own retention settings

These are Grok Build's own retention settings, which the Workbench reads back and displays next to each source, not a statement about xAI's data practices. The one changeable setting is set through the agent's own protocol, then verified by reading it back.

09

It runs on your machine, and collects nothing itself.

These are properties of the Workbench, checked in the code and against the recorded checks, not promises about Grok Build or xAI.

Loopback only

The Workbench server binds 127.0.0.1 and no other interface: its listen address, not a claim about Grok Build or xAI.

Zero telemetry

The Workbench sends nothing out: no analytics, no phone-home, no tracking of any kind.

Per-run access token

The Workbench gates its local interface with a fresh access token each time the server starts.

Strict Content-Security-Policy

The Workbench holds its page to a locked-down CSP that permits only what it needs and nothing more.

Agent output is text, never code

The Workbench renders every string the agent sends as text, and never runs it as markup or code.

MIT licensed · 1,400+ checks green

The Workbench is open source under the MIT license, with more than 1,400 deterministic checks that run green.

These claims are about the Workbench itself. They say nothing about what Grok Build or xAI do on their side. The Workbench is the local window you run; how the agent behaves upstream is the agent's own matter.

10

What you need to run it

Small on purpose. The server runs TypeScript directly: no build step, no dependencies to install.

Operating system
Linux (tested), or Windows via WSL2. The process-safety machinery is Linux-specific by design. macOS is unverified and not claimed.
Runtime
Node.js 22+. The server runs TypeScript directly: no build step, no dependencies.
Agent
Grok Build, installed separately. The Workbench is a window on that agent, not a substitute.
Install
From the public repository. Clone it, follow the README, and you are running.
